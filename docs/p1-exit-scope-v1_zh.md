## 冻结契约与解释

账本标识：`p1-exit-scope-v1`。于 2026-09-24 按源码修订 `4b1a30eb8fba079c3f9882b0d9eeb9318e65a331` 冻结。本账本为既有 P1 承诺分配稳定需求 ID，不宣布新编译器 profile，也不使仅类型检查 profile 变为可执行。下列 40 个需求行是清单分母，**不是**测试用例分母或通过结果。

权威输入包括[主路线图](../ROADMAP_zh.md)、[P1 叶子契约](roadmap/P1_zh.md)、[缺口矩阵](p1-gap-matrix.md)、[typed MIR 契约](typed-mir-profile.md)、[类型系统契约](type-system-profile.md)、[泛型契约](generic-profile.md)及[模块契约](module-profile.md)。叶子页面仍是唯一任务状态队列。本账本冻结含义和归属；下文实现观察描述的是记录基线，不是全新构建。

| 分类 | 含义 |
| --- | --- |
| `executable` | P1 必需的可执行类别或支撑它的编译器/证据不变量。缺失的降低、所有权检查或后端证据仍是要求。该分类不代表当前编译器接受所有列出形式。 |
| `check-only` | 既有词法、语法、解析、类型分析或结构 MIR 契约，不单独声称运行时能力。本账本其他行中相关的可执行要求仍然保留。 |
| `excluded` | 既有明确 profile 边界。范围列指出排除的 profile/功能，不能覆盖其他行的可执行要求。选择该 profile 时必须执行拒绝边界。 |

下文“声明范围”指所链接契约中的有界源码/类型形式，并使用 P1 可执行元素/值类别；不代表任意 Rust 语法、任意 trait 求解、无限递归或全部上游库。特别是，P1-04 接受某类型本身不承诺其 CLR ABI。反之，对已承诺的引用、切片、聚合、模式、闭包或 const 类别，既有能力拒绝属于实现缺口，不是将其排除的授权。

## 证据与变更规则

本双语清单及明确叶子归属满足 P1-06.01，不满足 P1-10.01/.02：具名用例、不可变哈希、精确测试分母及后端映射仍需各自版本化清单。执行不适用的支撑不变量采用诊断/结构/预算用例；每个可执行源码类别须经 P1-10.06 提供生成程序的 CoreCLR、ILVerify 及原生 Windows/Linux x64 AOT 证据。借用/Drop 差分用例另外使用固定 rustc 1.98 oracle。快照或解释器证据不能替代发射程序执行。

P1 叶子页面记录的 E6 基线为 `f4692c704b0c5432e05d7f08a00c6736ce3a1c75`：按各自记录范围包含 464 个测试工具、12 个平台、24 个回归及 16 个差分用例，另有 6 个聚合输入。它们都不是这 40 个需求的分母。缺失的引用/切片/模式/闭包/const/聚合/Drop/导入行为仍是实现工作；缺失的新平台证据仍是证据工作。二者都不能静默通过或省略。

需求 ID 及已接受义务保持稳定。范围内缺陷保留原 ID/负责叶子。扩展范围取得新版本/ID，并明确决定 profile；不得为结项篡改不可变语料或削弱本账本。两种语言必须保持等价标题、行顺序、分类、ID、归属、事实、诊断/profile 字面量及链接目标。叶子状态变化同时更新两种 P1 路线图语言，证据绑定实际测试的候选版本。
