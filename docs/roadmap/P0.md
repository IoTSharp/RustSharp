# P0 granular record: completed vertical architecture

English | [简体中文](P0_zh.md) | [Main roadmap](../../ROADMAP.md)

All rows are ✅ Complete **within the original P0 vertical-slice and feasibility scope**. This is a retrospective decomposition of the seventeen completed parent tasks, not a new implementation claim, a new test run, or a reopening of P0. Each parent is the aggregate of its listed children; `P0-GATE` is the aggregate of the three historical gate rows. Leaves have their own acyclic dependencies and do not wait for their own phase gate.

The evidence source is the existing main-roadmap record for commit `286f139`, collected during 2026-09-02 through 2026-09-04 with .NET SDK 10.0.400 and runtime 10.0.11. **W** means [Windows run 33857817622](https://github.com/IoTSharp/RustSharp/actions/runs/33857817622), **L** means [Linux run 33857817620](https://github.com/IoTSharp/RustSharp/actions/runs/33857817620), and **H** means both historical CI archives and their recorded main-roadmap evidence. These references are preserved, not freshly downloaded or rerun in this documentation change.

Each platform archive records 14 files/seven JSON reports, 73/73 executable tests, 4/4 vertical differential, 6/6 syntax, 6/6 name resolution, 4/4 IO smoke, standalone ILVerify and native execution. The separately recorded local 74/74 run is a later local count, not the CI denominator. Local WSL SDK mismatch and missing sqlite3 were skipped/blocked locally; the actual native CI reports supply the successful Linux/SQLite evidence. No local skip is relabeled as success.

Named source/test files below are current inspection locations for the historical deliverable; their present contents may include later work. The eight CLR LIR and eight ownership cases, generic/trait model, and managed-hybrid probes demonstrate bounded feasibility only. They do not close P1 source-level semantics, generated destructor failure handling, later API profiles or new platforms. Concurrent publication collision hardening, filesystem-alias handling and externally locked artifact recovery remain later gates under the main roadmap's boundary.

The recorded harness command is `dotnet run --project tests/RustSharp.Tests/RustSharp.Tests.csproj -c Release --no-restore`; it is an executable harness, not `dotnet test` discovery. Existing evidence identifies tool/profile/platform, fixed counts and bounded process/cleanup information. Ignored `artifacts/` paths name recorded reproducible outputs and are not newly committed reports. This documentation work does not change `global.json`.
