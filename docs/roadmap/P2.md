# P2 granular delivery contract

English | [简体中文](P2_zh.md) | [Main roadmap](../../ROADMAP.md)

P2 contains **15 parent tasks, 94 implementation leaves, and 7 gate leaves**.
Every leaf below is ⏳ Planned. Existing Cargo parsing, process runners, runtime
probes, and CLI commands are foundations; they are not evidence that these P2
contracts have passed. The P1 gate remains a hard prerequisite for P2 completion.

Each `.01` leaf freezes a versioned scope manifest before implementation: named
APIs, signatures, features, platform combinations, supported and rejected cases,
and a fixed test denominator. It must preserve its parent's required surface;
choosing exact members cannot remove a named family from that parent. Expansion
creates a new version and new work items, not new hidden conditions at closure.
For a completed leaf, retain its exact manifest and evidence; do not reopen it
merely because a later profile grows. A parent passes only when all its leaves
pass. P2 passes only when all 15 parents and all 7 `P2-GATE` leaves pass, after
`P1-GATE`. Design may start early; dependencies must pass before closure.

All new paths and test targets below are **planned deliverables**, not assertions
that those files or commands already exist. `test:<name>` denotes a planned,
filterable test target, whose concrete bounded invocation must be registered in
its scope manifest. Evidence for every leaf is a machine-readable report keyed
by its ID and manifest hash, containing commit SHA, tools/versions, RID, command,
denominator, pass/fail/skip counts, time/resource limits, PID/start/parent,
cleanup, and failure reasons. Required cases cannot be skipped; unsupported
cases must produce the frozen diagnostic. Report archives need a stable CI URL
or provenance. Runtime rows require real generated programs, not host-library
simulation. Shared directories below identify review ownership; parallel workers
must reserve distinct files before editing them.

The P2 Web starter is a runnable minimal server using the declared `std::net`
surface; it makes no `axum`/`reqwest` claim. Rich Web profiles add template versions
in P4, avoiding a P2 → P4 → P2 dependency cycle. The interactive REPL is explicitly
CoreCLR/JIT-only. Visual Studio evidence is required on Windows; the shared LSP,
VS Code, CLI, and application platform gates cover Windows and Linux x64.
