# P2 颗粒化交付契约

[English](P2.md) | 简体中文 | [总路线图](../../ROADMAP_zh.md)

P2 包含 **15 个父任务、94 个实施叶子和 7 个门槛叶子**。
下列所有叶子均为 ⏳ 计划中。现有 Cargo 解析、进程运行器、运行时探针和 CLI 命令
是实现基础，并不证明这些 P2 契约已通过。P1 门槛仍是 P2 完成的硬前提。

每组 `.01` 叶子先冻结版本化范围清单：具名 API、签名、feature、平台组合、支持与
拒绝用例，以及固定测试分母。清单必须保留父任务要求的表面；选择具体成员不能删掉
父任务已列出的功能族。扩大范围应新增版本和工作项，不能在关闭时追加隐藏条件。
叶子完成后保留其精确清单和证据；不能仅因后续配置档扩展而重新打开。
父任务仅在本组所有叶子通过后完成。P2 仅在 `P1-GATE` 通过之后，全部 15 个父任务
和 7 个 `P2-GATE` 叶子均通过时完成。可以提前设计，但关闭前必须满足依赖。

下文所有新增路径和测试目标均为**计划交付物**，不表示文件或命令已存在。
`test:<name>` 表示计划提供的可过滤测试目标，其具体有界调用必须登记在范围清单中。
每个叶子的证据都是以任务 ID 和清单哈希为键的机器可读报告，记录提交 SHA、工具及
版本、RID、命令、分母、通过/失败/跳过计数、时间/资源上限、PID/启动时间/父进程、
清理和失败原因。必需用例不得跳过；不支持用例必须给出冻结的诊断。报告归档需要稳定
CI 链接或来源证明。运行时条目要求真实生成的程序，不能用宿主库模拟代替。
下文共享目录表示审查所有权；并行修改前必须再划分互不冲突的具体文件。

P2 Web 起始模板是使用已声明 `std::net` 表面的最小可运行服务器，不承诺
`axum`/`reqwest`。P4 的完整 Web 配置档新增模板版本，避免 P2 → P4 → P2 的依赖环。
交互 REPL 明确仅支持 CoreCLR/JIT。Visual Studio 必须有 Windows 证据；共享 LSP、
VS Code、CLI 和应用平台门槛覆盖 Windows 与 Linux x64。
